# Specs

This folder contains living specifications for behavior that should be changed through spec-driven development.

## Spec-Driven Workflow

1. Update the relevant spec before changing production code.
2. Capture the expected behavior, failure handling, configuration, and test impact.
3. Implement only the behavior described in the spec.
4. Add or update tests that map back to the spec acceptance criteria.
5. Keep commits aligned with spec sections when the work is large.
6. If implementation discovers a better design, update the spec first, then continue coding.
